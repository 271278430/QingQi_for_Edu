# 系统分区架构与全部历史清理

2026-11-22。用户要求清空本教育项目全部历史，并把 Agent Loop、工具系统、记忆系统、权限管理及四业务模块画清楚，图必须与实现一致。

## 历史清理

“全部历史”是两个本机入口共享的学习数据库内全部账户的会话、辅导任务、消息、图片、工具/模型调用账本、对话状态、episode/fact 与新作答事件、练习任务及路线选择。教材、题库、模型/账户配置、产品设置、学习目标和初始学情画像保留。导入会话/历史题展示也停用，不在重启或索引升级时重新导入；初始画像中历史会话数量置零。

清理使用唯一 Store 的事务命令：服务端 can_manage + Origin/CSRF → request_id 幂等准入 → 检查有效执行租约 → epoch 增加 → 子表先于父表删除 → 保存仅含计数的清理回执。重放同一编号不能再次清除后来建立的对话。执行中拒绝清理；与清理并发且已通过会话鉴权但尚未进入 Agent 的旧请求，必须在 Store.begin 内以历史 epoch 拒绝，不能重新写回已删除会话。管理员后台可显式确认后清空，当前用户直接授权的清理无需再次询问。

Web 客户端收到清理成功时更新 generation/selection 并清空已接受会话视图、待发送引用与附件，防旧回包覆盖；设置页保留，四业务页重新读取。其他打开的页面刷新时不得显示旧历史。

停止历史导入后，源快照残留的历史题标记也不参与新作答独立性判定；新作答仍按本产品当前的提示/重试/题目事件核验，初始学情估计不冒充一道题已做过。

## 分层架构表达

总览采用可点选的分区架构板，首屏清晰展示：Web四业务入口、权限管理、Agent Loop、工具系统、模型/子Agent、Skills、记忆系统、学情/路径/推荐服务、数据与持久化、设置运维。只画模块调用/读写边界，不把每个执行步骤塞进总图。块中显示职责和实际实现状态，点块进入子图。

子图分别画真实分支与循环：Agent的调用→观察→决策、工具的注册/权限/参数绑定/本地或MCP或Worker三分支、记忆的当前题/临时状态/episode/fact/学习事件及读取/提交/清理、权限的账户/CSRF/资源归属/管理权限/工具只读能力交集、模型的GLM/Flash/受控解题/8B/27B分工。四业务模块画共享学情闭环而非相互独立的示意图。

每个子图附状态所有者、接口、真实源码及符号核对、ZCode实际复用和支持边界。图中能力不得以“文件存在”冒充实现：新增源码绑定检查并区分启用/未启用的模型、已支持/未支持能力。该图描述当前Python教育Loop+ZCode工具运行时，不声称原样复用ZCode编码Agent的全部记忆与权限体系。

架构数据由一个服务端目录定义，客户端不复制模块事实；当前API的模块列表与分区板使用同一份数据。详情仍使用ZCode Mermaid，支持放大与完整滚动。权限模块独立；所有图在两种主题、桌面及手机可读且可操作。

## 验收

先维护HTTP与浏览器验收再实现。覆盖清理范围、源数据保留、导入历史不复现、跨入口读取为空、幂等旧命令不删新记录、无权清理与无CSRF拒绝、执行租约冲突、旧准入epoch拒绝、清理后正常新建和练习。架构需验证总览独立系统块、每块可进入真实子图、Agent循环/工具三分支/记忆分层/权限拒绝路径、源码符号存在、实际能力启用状态、放大/刷新/手机/主题。运行根typecheck、lint、Hooks专项、架构门禁与受影响服务/HTTP/浏览器回归，最后清理真实数据并重启验收地址。
