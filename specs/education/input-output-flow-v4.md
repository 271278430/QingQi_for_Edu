# 默认全景以输入到输出的执行流程为主线

2026-11-22。用户要求明确一系列输入→处理→输出步骤。默认视图为“输入输出流程”，保留“系统关系”作为另一视图；两者引用同一模块目录和同一SVG渲染器，不重新清理或改写学习数据。

## 对话辅导主线

按01–08由上到下展示，每步明确输入、处理、输出：

1. 学生输入与Web提交：文字/1–3张图片/历史题引用 → 组装所属会话及请求编号 → 学习请求。
2. 身份与准入：账户/Origin/CSRF/资源归属 → Store幂等、会话租约、历史epoch检查 → 可执行请求；失败输出错误，缓存结果直接重放。
3. 题目和学情依据：恢复当前题及同题对话、必要时Flash转写新图、读取学习证据 → 绑定的原题与学情依据。
4. 教学计划与上下文：意图、难度、学生要求与学情 → 帮助方式/长度/DAG、Skills指导、有界记忆和工具白名单 → 本轮计划与受限上下文。
5. Agent循环：Controller选择直接回复或受控工具调用，观察后继续决策 → 候选回复与真实观察。模型和本地受控数学Controller均按实际能力参与，不强制每次调用LLM。
6. 回复核验：结构、证据、实际学生步骤、答案许可、图形参数核验 → 可提交回复；可修复时回到05，预算耗尽时停止并返回明确失败。
7. 同事务保存：回复、episode、当前题及符合合同的作答证据 → 可恢复的会话和学习事件。
8. Web输出：投影/渲染 → 自然辅导、提示或参考解答、图/表/动画及原附件。学生后续输入启动下一轮。

主图包含明确的开始、结束、缓存重放和拒绝/失败出口。编号表示执行顺序；支撑系统通过侧边虚线连接对应步骤，不与主线混淆。Loop内部另画“决策→调用→观察→再决策”。
