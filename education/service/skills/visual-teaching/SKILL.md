name: visual-teaching
description: Choose an optional, bounded visual aid for the current math tutoring turn.
---

Choose a visual proactively when the current problem's mathematical structure benefits from it; do not wait for a drawing keyword. In function/zero/extrema problems use the corresponding function curve; in a nonnegative square-root plus absolute-value equation use the corresponding two expression curves, their domains and zeros. Ordinary conversation can remain text. Call render_teaching_visual at most once with one or two figures, then explain what feature of THIS question the figure clarifies.

Explicit drawing is an action: connect points using coordinates.segments with source/target indices, never merely tell the student to imagine lines. Read visual_task and use only the owned given points; do not add the unknown answer vertex. Describe a drawing as completed only after visual_aids contains the actual segments. coordinates also supports polygons and circles. Use clean point names, not duplicated coordinates in labels.

Use function_plot with linear/quadratic/cubic coefficients and a bounded domain for function behavior; area_model with numerator, denominator and rectangle/circle for fractions. Function coefficients and markers inferred from an unknown parameter must use analyze_function's approved figures when available; solution figures require owner-authorized disclosure. Additional animations: coordinate_drawing draws actual segments step by step, fraction_fill builds a partition, pythagorean reveals squares on right-triangle sides. The tool computes samples, geometry and frames. These are bounded teaching demonstrations, not a general proof engine.

For animation requests use animation_scene with a supported template, bounded params and duration 8–20. The tool computes frames; never supply frames, scripts or external assets. Consider teaching_plan.visual.recommended_template for abstract concepts or repeated difficulty. Ordinary explanations need not animate. After a visual, explain how to read it briefly instead of repeating its table or diagram code.

Owned identities use identity_probe from visual_task.arguments: compare the same equation at x=0,1,2 and derive coefficient/constant conditions. Do not replace it with an arbitrary line plot. Its equation, disclosure mode and power goal must match the owner-provided parameters. Owner-approved function_reasoning is preferred for a supported original function problem. Generic curve exploration uses function_trace with function/a/b/c/domain inside params, not beside kind/template. Do not supply frames. A request declining animation must be respected.

Use owner-approved function_reasoning or nonnegative_reasoning to show actual curves, meaningful axes and the original problem goal. These templates bind the original equation and disclosure mode; never supply stages, sampled curves or solved values yourself. Three parameter cases compare the original function family, not a new exercise with different coefficients. Unknown parameters use explicitly symbolic/normalized axes; do not label a trial as the determined answer. Nonnegative curves have distinct input variables; do not pretend a and b share one axis. Owner-compiled square_root/absolute function_plot figures are available for static nonnegative teaching. Each moving point must demonstrate the current mathematical inference; decorative bars and unrelated stories are insufficient.

Prefer one figure unless a second is necessary for comparison. Follow the selected kind's required fields: scene needs nodes AND edges, table needs columns AND rows, coordinates need x AND y for every point. When protocol_error is provided, correct that specific field error or continue with ordinary text if a reliable figure cannot be supplied. Do not repeat the rejected parameters.

Only plain labels and bounded structured data are allowed. Never send HTML, JavaScript, URLs or files. Prefer example for an analogous worked example and clearly distinguish it from the actual question. problem is reserved for explicitly given numbers from the currently bound question. Graph shape and arithmetic computation are validated by the tool; a general scene is illustrative, not a verified geometry proof.

Respect allow_final_answer: do not hide final answers in labels, coordinate values, table cells, chart heights or a completed number-line calculation. Hint graphs keep original coefficients and intervals, use unresolved conditions or clearly labeled parameter trials, and stop before solved parameters and final results. Respect explicit no-graph/no-animation requests; static curves are appropriate when animation is declined. Do not invent learner progress or mastery. The figure belongs to this turn; previous figures must not be silently reused for a new problem.
